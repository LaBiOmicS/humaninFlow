LaBiOmicS Workflow series · HumaninFinder 1.0.0b4

Find Humanin and SHLP1–6 in one mitogenome or ten thousand.

humaninFlow runs HumaninFinder over every FASTA you give it, in parallel, then joins the predicted peptides to your sample metadata in a single cohort table. Use Nextflow or Snakemake: both produce the same files.

What it finds

Seven short peptides inside one ribosomal RNA gene.

Humanin and SHLP1–6 are encoded by short open reading frames inside MT-RNR2, the mitochondrial 16S rRNA gene, on both strands. Ordinary gene finders skip them. HumaninFinder locates the gene by synteny, reads each frame under the right genetic code and checks Humanin against the Pfam PF15040 profile. This is what it reports for the human reference mitogenome in the example data.

Pipeline

Three steps, the same in both engines.

Each input FASTA is checked and analysed on its own, so a glob of a thousand files runs as a thousand parallel jobs. Everything is then gathered into one cohort summary.

Lint the FASTA

humanin-finder lint rejects malformed records, illegal symbols and duplicate IDs before any compute is spent.

HUMANIN_LINTrule lint

Predict the peptides

humanin-finder predict (or scan) locates MT-RNR2, translates the frames and scores Humanin against PF15040. Writes CSV, FASTA, GFF3, BED and a run record.

HUMANIN_RUNrule predict

Summarise the cohort

One shared script merges all predictions with your metadata, collapses identical peptides into alleles and writes a Markdown report.

SUMMARIZE_COHORTrule summarize

Metadata is matched on an accession, isolate, sample_id or id column, with or without the version suffix (NC_012920.1 = NC_012920). Rows with no match keep their predictions and get N/A.

Quick start

Run it on your data.

Clone the repository and pick an engine. With a container or conda profile you need nothing else installed; without one, install the engine with pip install humanin-finder==1.0.0b4.

Best for clusters and cloud executors. --input takes a single file or a quoted glob.

# 1 · try the bundled example (human + mouse)
git clone https://github.com/LaBiOmicS/humaninFlow.git && cd humaninFlow
nextflow run workflow/nextflow/main.nf -profile test,docker

# 2 · your cohort: vertebrate mitochondrial code, circular genomes
nextflow run workflow/nextflow/main.nf -profile apptainer \
  --input 'cohort/*.fasta' \
  --metadata samples.csv \
  --table 2 \
  --outdir results/cohort

# 3 · NUMT screen in nuclear scaffolds: every candidate, standard code, linear
nextflow run workflow/nextflow/main.nf -profile docker \
  --input assembly.fasta.gz --command scan --table 1 --circular false \
  --outdir results/numts
-profile test
Bundled example FASTA and metadata.
-profile docker · apptainer · singularity
Runs every step in ghcr.io/labiomics/humaninfinder:1.0.0b4.
-profile conda
Builds workflow/envs/humaninfinder.yaml.
-profile slurm
Submits each task to SLURM; combine with a container profile.

Best for a single workstation or server. Paths are relative to where you run snakemake, normally the repository root.

# 1 · bundled example, with HumaninFinder from conda
snakemake -s workflow/snakemake/Snakefile --cores 4 --use-conda

# 2 · your data
snakemake -s workflow/snakemake/Snakefile --cores 8 --use-apptainer \
  --config input_fasta=cohort.fasta \
           metadata=samples.tsv \
           table=2 \
           outdir=results/cohort

# 3 · no metadata merge
snakemake -s workflow/snakemake/Snakefile --cores 4 \
  --config input_fasta=cohort.fasta metadata=""
workflow/snakemake/config/config.yaml
Defaults for every key; override any of them with --config key=value.
--use-conda
Same environment file as the Nextflow conda profile.
--use-apptainer
Same container image as the Nextflow profiles.

Parameters

One set of options, two spellings.

Nextflow takes them as --name value; Snakemake takes the same names as --config name=value, except for the input file.

NextflowSnakemakeDefaultMeaning
--inputinput_fastarequiredFASTA, plain or gzip. Nextflow also accepts a quoted glob.
--metadatametadatanoneCSV or TSV joined to the predictions by sample ID.
--outdiroutdirresults/<engine>Where raw_predictions/ and summary/ are written.
--commandcommandpredictpredict keeps the best frame per genetic code; scan keeps every non-redundant hit.
--tabletableautoNCBI genetic code: 2, 1, 2,1… auto uses 2 for records ≤ 50 kb or labelled mitochondrial, 1 otherwise.
--circularcirculartrueSearch across the origin of records ≤ 50 kb.
--all_candidatesall_candidatesfalseWith predict, report every non-redundant candidate.

--no_shlp · --no_syntenyno_shlp · no_syntenyfalseAnnotate Humanin only / skip locating MT-RNR2 by synteny.

Outputs

What you get back.

<prefix> is the input file name without its .fa/.fasta/.fna/.gz extension, so each input keeps its own set of raw files.

raw_predictions/ · one set per input

<prefix>_results.csv
Every call: coordinates, strand, frame status (Complete, Incomplete, Interrupted), HMM and synteny scores, evidence tier, peptide sequence.
<prefix>_results.fasta
The translated peptides.
<prefix>_results.gff3 · .bed
Tracks for IGV or JBrowse 2; BED splits features that cross the origin.
<prefix>_run.json
Run record: command line, options, tool version and SHA-256 of the input.

summary/ · one per run

cohort_humanin_summary.csv · .tsv
All predictions from all inputs, with every metadata column appended.
cohort_unique_peptides.fasta
One record per distinct peptide sequence, ranked by how many samples carry it.
COHORT_ANALYSIS_REPORT.md
Counts per peptide and frame status, metadata match rate, and a table of Humanin alleles.

Use whichever your lab already runs.

Both engines call the same HumaninFinder release and the same summary script. Continuous integration runs both on the example data on every change and fails unless their outputs are byte-for-byte identical.
